# Plan-first workflow — 계획 문서 우선

코드를 작성/수정하기 전에 **계획 문서를 먼저 작성하고 승인을 받는다.**

## 순서

1. **계획 문서 작성** — `plans/YYYY-MM-DD-<짧은-슬러그>.md`
   - 목표
   - 변경할 파일 목록
   - 단계별 작업 (각 단계의 검증 체크포인트 포함)
   - 검증 방법 — `pytest tests/ -q`, `ruff check`
   - 위험 요소 / 영향 범위
   - `writing-plans` 스킬이 있으면 그 형식을 따른다.
2. **검토 대기** — 계획을 사용자에게 제시하고, **명시적 승인 전까지 파일을 편집하지 않는다.**
3. **실행** — 승인된 계획대로 구현. `executing-plans` 스킬이 있으면 그 흐름을 따른다.
4. **편차 발생 시** — 계획에서 벗어나야 하면 멈추고 변경을 설명한 뒤 다시 승인을 받는다.

## 예외 (계획 문서 없이 진행 가능)

- 오타·주석·문서 한 줄 같은 사소한 수정
- 사용자가 "계획 없이 바로 해줘"라고 명시한 경우
